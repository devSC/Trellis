# 产品需求文档（主文档）

## 第一章：产品总述

### 1.1 产品用途

- 产品类型：候选人简历管理控制台。
- 目标：支持简历导入、查询、维护与同步回执，确保候选人信息可持续更新、可检索、可审阅。

### 1.2 目标用户

- 用户角色：招聘顾问、招聘运营、数据运维。
- 核心场景：批量导入简历后，快速筛选候选人、修正基础信息，并在必要时通过命令行触发全量同步。

### 1.3 用户核心痛点

- 导入完成前缺少稳定的任务回执，招聘运营难以判断哪些简历已成功入库。
- 列表筛选条件较多时，招聘顾问难以快速定位到目标候选人。
- 基础字段修正与批量同步入口分散，容易造成数据状态不一致。

### 1.4 主要功能及核心场景

| REQ-UC-ID | 场景名称 | 业务目标 | 主路径摘要 | 备注 |
| --- | --- | --- | --- | --- |
| REQ-UC-001 | 导入并结构化简历 | 将上传的简历文件稳定转化为可检索记录 | 上传文件 -> 创建导入任务 -> 解析入库 -> 返回任务回执 | 对应导入任务页与导入 API |
| REQ-UC-002 | 检索并定位候选人 | 支持顾问按关键词和条件快速定位目标简历 | 输入检索条件 -> 刷新列表 -> 浏览结果 -> 进入详情 | 对应列表页与查询 API |
| REQ-UC-003 | 维护候选人基础信息 | 保证关键字段可被及时修正并回写系统 | 进入详情 -> 修改字段 -> 提交保存 -> 返回列表 | 对应详情页与更新 API |
| REQ-UC-004 | 通过 CLI 触发全量同步 | 在运维窗口触发全量同步并拿到可追踪回执 | 执行命令 -> 校验参数 -> 触发同步 -> 输出结果摘要 | 对应 CLI 文档 |

## 第二章：入口组织结构（本示例为页面组织结构）

### 2.1 页面清单

- P-001 简历列表页
- P-002 简历详情页
- P-003 导入任务页

### 2.2 页面关系（摘要）

- 导入任务页 -> 简历列表页。
- 简历列表页 -> 简历详情页。
- 简历详情页保存后返回简历列表页。

### 2.3 页面简述（摘要级）

页面名称：P-001 简历列表页
- 功能：展示简历检索结果并支持筛选。
- 场景：承接 `REQ-UC-002`，用于顾问搜索与定位候选人。
- 页面关系：可从导入任务页进入，后续可跳转详情页。
- 主定义链接：`requirement-web-console.md` 第三章。

页面名称：P-002 简历详情页
- 功能：展示候选人详情并支持基础编辑。
- 场景：承接 `REQ-UC-003`，用于维护候选人基础字段。
- 页面关系：前置为简历列表页，保存后返回列表页。
- 主定义链接：`requirement-web-console.md` 第四章。

页面名称：P-003 导入任务页
- 功能：上传简历并查看导入任务状态。
- 场景：承接 `REQ-UC-001`，用于创建导入任务并查看解析结果。
- 页面关系：完成导入后可进入简历列表页。
- 主定义链接：`requirement-web-console.md` 第五章。

### 2.4 非 UI 入口摘要（摘要级）

入口名称：CLI-INTENT-001 全量简历数据同步
- 入口类型：CLI-only。
- 场景：承接 `REQ-UC-004`，用于运维窗口触发全量同步并获得可判定回执。
- 主定义链接：`requirement-cli-command.md`。
- 页面组织：不适用，原因：该场景无 UI 入口，由 CLI Command 主定义承接。
